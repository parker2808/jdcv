# CV export

## Problem and why it matters

A tailored curriculum vitae (CV) must be editable in Word and readable as a PDF without drifting between versions. Applicant tracking systems (ATS) often extract plain text, so an attractive file that loses Vietnamese accents or reading order is not acceptable. For example, a fictional applicant's heading `Kỹ năng` must remain readable in both output formats.

## Goals and non-goals

Produce a document (`.docx`) from structured CV JSON and convert that exact document to PDF. Provide a fallback HTML-to-PDF renderer when office conversion breaks layout. Do not generate a second, independent source of CV claims or put a real template or CV in the public repository.

## Design and data shape

The input has `basics`, bilingual `summary`, `experience` with dated projects and bilingual bullets, `skills`, `education`, `locale`, `templateId`, and `jdId`. Each bullet may carry a `factRef` and `embellishmentId`; export reads only an approved CV version. For example, a fictional `Alex Example` CV may have a project alias `Project A` and a Vietnamese bullet, never a real employer's identifying details in tests.

Use docxtemplater tags in a Word template to produce DOCX. Send those DOCX bytes to Gotenberg's LibreOffice route and return PDF only after checking response type and output. If its layout check fails, a separate HTML template rendered by Playwright/Chromium can make the PDF; compare extracted text to the DOCX before delivery and clearly record the fallback route. Embed or provision Open Font License fonts with full Vietnamese glyph support, such as Be Vietnam Pro or Noto Sans, for both render paths. Main content uses ordinary paragraphs and conventional section headings, not text boxes or layout tables. Extract text from both files and compare section order, key phrases, and Unicode diacritics against the approved JSON.

Phase 1 keeps owner outputs in the private job workspace and sends them through Telegram. Phase 2 stores files as private raw objects with an authenticated download, expiring after 30 days. Gotenberg runs in a free container only if preview memory measurements support it; otherwise use the tested fallback or owner-only Mac route, without changing an outside user's privacy or routing policy. CI uses a Gotenberg service container on standard GitHub Actions runners with only fictional fixtures.

## Constraints and risks

Reject exports if any embellishment lacks line approval or a passing defence entry. Risks include font substitution, LibreOffice layout changes, HTML fallback drift, and free-tier memory limits. Keep original CV content and generated bytes out of logs and Git.

## Acceptance criteria and verification

1. **AC1:** A fictional bilingual JSON fixture produces a valid DOCX and a PDF converted from those exact DOCX bytes. Check parsing and a Gotenberg service-container integration test on GitHub Actions.
2. **AC2:** Text extracted from both formats retains all fixture section headings, the approved bullet text, Vietnamese accents, and the same section order. Check normalized Unicode text assertions and manual page inspection of the fixture.
3. **AC3:** When LibreOffice conversion fails or layout validation fails, the HTML-to-PDF path either passes the same text assertions or returns a visible error; it never silently returns mismatched text. Check an injected failure integration test.
4. **AC4:** An unapproved change blocks export; expired files cannot be downloaded after 30 days. Check an approval-gate test and a clock-controlled storage expiration test.

## Open questions

Measure Gotenberg memory in the free preview environment and specify a stable layout-diff tolerance. Finalize the allowed template tags before offering user-uploaded templates.
