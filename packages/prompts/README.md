# Prompt package

`@jdcv/prompts` builds small instructions for independent Generator, Interviewer, Examiner, and readability-review threads. It never reads a curriculum vitae (CV) or job description (JD), so the worker can keep both in its private job workspace. For example, a worker passes `/private/jobs/alex-example/jd.txt` as a path instead of inserting the fictional JD text into a turn.

Pass `JobFiles`, `Audience`, and a revision number (zero, one, or two) to each render function. `generatorPrompt` requests a bilingual version 2 module compatible with `@jdcv/contracts`; `interviewerPrompt` asks about each mandatory requirement and proposed CV edit; `examinerPrompt` asks for scored answers; `readabilityPrompt` reviews every entry independently. Each result stays within 6,144 UTF-8 bytes or throws. The worker must create private files, relay threads, validate model output, and enforce revision limits; none of those actions happen here.

Use `evaluateExamination(result, mandatoryRequirementIds, embellishmentIds)` after checking the output. It passes only when the answer average is at least four, every mandatory requirement has an answer, each embellishment defence scores at least four, and nothing is critical. Use `evaluateReadability(result, entryIds)` to require every expected study entry to score at least four. For example, a score of five cannot make up for a missing mandatory answer. The worker must derive required IDs from the JD and private proposal record rather than trusting an Examiner to supply a complete list.

`canProposeEmbellishments` defaults to true for the owner. An outside user needs both an explicit opt-in and acceptance of the current terms. `checkPlausibility` rejects changes to core CV facts and warns when a project detail has no support in supplied project facts. It does not grant line-by-line approval or authorize export. Never place actual CV data, JD text, personal identifiers, or proposal contents in this public repository.
